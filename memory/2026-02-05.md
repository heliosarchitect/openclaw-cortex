### Critical Fix (16:55)
**Timestamp mismatch bug** - preventing trades from closing:
- Position dict: datetime.now() → object A
- Database INSERT: datetime.now() → object B (microseconds different)
- close_position() matched on timestamp → never found BUY → trades stuck OPEN forever

**Solution:** Use single ISO timestamp string for both position dict and database.

**Impact:** Win rate jumped from 45.1% → 52.0% after fix. Trades finally closing.

## Lessons Learned

### 1. Volume Strategy Wrong for Deployment Reality
- Requires 20-minute warmup (20 data points)
- 8 restarts × ~25 min avg = 2+ hours lost
- **Should have picked strategy with <5 data point lookback**

### 2. Code Quality Cascade
- Deployed 8 bugs in 90 minutes
- Each fix revealed next issue
- **Root cause:** Rush to deploy, no isolation testing

### 3. Matthew's Expectations
- Action > Explanation
- Fix > Report
- Deploy working code > Deploy any code

### 4. What Actually Worked
- Timestamp fix (critical)
- Volume history persistence
- Strategy search (7,079 profitable strategies found)

## What's Next
- Volume strategy has wrong design for frequent restarts
- Need strategy with minimal lookback OR graceful degradation
- Test volume capture in isolation before deploying
- One fix per deployment cycle
- Verify edits applied before restarting

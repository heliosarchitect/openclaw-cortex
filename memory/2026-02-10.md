## Key Insights from Matthew

### 1. Concurrent Architecture, Not Sequential
GPU runs multiple small models simultaneously. 32GB ÷ 2GB = 16 concurrent specialists.
Not "swap one model at a time" — multiple daemons always resident, watching their domains.
Security agent + QA agent + email triage + XTTS all loaded at once.

### 2. Token Offload Rate is the Metric
Not VRAM efficiency, not dollars per model. Every token running locally = money saved.
Maximize coverage (more task types handled locally), not per-model quality.

### 3. Dynamic VRAM — Don't Shoehorn
Ollama evicts idle models automatically. Full 32GB available to active model.
Small daemons stay resident; large models (qwen2.5:32b) swap in for complex tasks.
Don't think "what fits alongside X" — think "what's the fleet composition."

### 4. The Fleet Name Wasn't Accidental
fleet.wood → Fleetwood. Starfleet. A fleet of servers, models, agents.
Each specialist running their station on the bridge. The name was always the vision.

### 5. Sub-Agents on Local Models = 24/7 Free Productivity
"Imagine what you could do if you could run sub agents 24/7"
The API is the escalation path, not the default. Local = the operating system.
